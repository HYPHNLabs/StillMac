# Roadmap

This is directional, not a release promise. The published beta is v0.1.1.
M1 and M2 are a source candidate pending integration review, release approval
and field validation. See [acceptance gates](docs/M1-M2-ACCEPTANCE.md).

## M1: evidence before cleanup

- Explain complete, partial and unknown logical sizes, exclusions and rebuild costs.
- Make terminal selection and exact-plan approval straightforward.
- Inspect explicitly selected project scopes for supported artifact families.
- Offer a locally prepared Agent Skill that negotiates CLI capabilities and preserves human approval.
- Keep Homebrew inventory-only: the native cleanup interface does not provide the required exact-root action binding.

## M2: explain what changed after a coding session

- Save bounded private residue snapshots and compare only compatible evidence.
- Separate growth from receipt-linked regrowth and never infer filesystem free space.
- List and remove protection deliberately, requiring fresh planning after changes.
- Retire only explicitly registered user-managed linked Git worktrees through the separate retirement contract, revalidation, exact approval and receipts.
- Provide explicitly invoked session reports; no scheduler or installed client hook.

## Prove usefulness before expanding

Start with developers running several coding-agent sessions who already face a
storage decision. Ask ten opt-in pilots to use the same evidence-first workflow.
Measure time to a decision, useful cleanup or keep decisions, missing resource
families and independent repeat use. Do not treat downloads, fixture tests or
new features as evidence of retention. Targets and current unmeasured states
are in the acceptance document.

A broad Mac-cleaner pitch would hide the product's strongest reason to exist:
knowing what a coding session left behind and whether a specific action is
supported by evidence. Demonstrate that workflow with synthetic examples and
honest limits before widening the offer. No outreach or publication is automated.

## Release gates and later contracts

- Independent security and specification review for the integrated candidate.
- Version-qualified live agent evidence, reviewed distribution assets and platform runtime evidence.
- Signing and notarisation only after activation and verification.
- Additional resource families or a native Homebrew action only under separate contracts.
- Better process-baseline interpretation remains separate from residue measurements.

## Explicitly excluded

Agent-managed worktree retirement, Codex runtime cleanup, generic deletion,
process termination, sudo, force, automatic cleanup, telemetry, cloud services,
and LLM-driven safety decisions.
