# StillMac distribution and lifecycle contract

Versioned release archives are `stillmac-vX.Y.Z-darwin-arm64.tar.gz` and `stillmac-vX.Y.Z-darwin-amd64.tar.gz`; each contains only the executable `stillmac`. `SHA256SUMS` is generated beside them. The source-candidate `scripts/install.sh` is intentionally fail-closed and cannot install remotely. A release process must substitute a concrete, independently trusted SHA-256 digest for `@TRUSTED_MANIFEST_SHA256@` in `scripts/install.sh.tmpl`, only after the exact versioned manifest and release provenance/attestation have been reviewed. The generated installer verifies that pin before parsing any archive hash; a modified archive plus modified manifest is therefore rejected. This pin is an independent binding only when the installer itself is obtained from a trusted repository/tag. It is not a claim that checksums alone authenticate a release.

Release binaries are built with `go build -buildvcs=false -trimpath` so package contents do not depend on commit metadata or workspace state. After `scripts/package.sh vX.Y.Z DIST` completes, `scripts/activate-installer.sh vX.Y.Z DIST [OUTPUT]` validates the exact manifest and both artifacts, computes the manifest digest, and exclusively creates the trusted installer. Publication opens the output parent with `O_DIRECTORY|O_NOFOLLOW`, validates its descriptor, then creates the basename with descriptor-relative `O_CREAT|O_EXCL|O_NOFOLLOW` mode `0755`, writes and syncs it, and syncs the directory. Existing regular files and symlinks are never replaced; failures clean up only a file created by that invocation. Activation is a private preparation step; it does not publish or activate the checked-in installer.

The supported target is macOS 14+ on Apple Silicon (`arm64`) or Intel (`amd64`); cross-build is not runtime evidence. Installation is per-user at exactly `$HOME/.local/bin/stillmac`; `STILLMAC_BIN_DIR` and `STILLMAC_DATA_DIR` are not supported production controls. HOME, `.local`, and `bin` must be absolute, real directories owned by the invoking uid and not group/world writable. Components are revalidated by device/inode before publication/removal. The documented boundary excludes a same-user attacker who can mutate HOME or its components between checks; POSIX shell cannot provide descriptor-relative no-follow rename/unlink. Uninstall removes only the executable and keeps `$HOME/Library/Application Support/StillMac`.

Collection is never automatic: `sample` requires an explicit user invocation and consent in the surrounding workflow. Cleanup is also never automatic: `clean` requires a TTY and exact plan confirmation, while scripted use separates `plan` and `apply`. Errors are concise and must not expose command arguments, environment, credentials, or unrelated paths. StillMac has no network client, telemetry, LLM, scheduler, service, automatic update, recursive deletion, cache-root rename, or arbitrary remediation. Its one active action is the separately contracted verified owner-native Go build cache clean. Retained data follows [PRIVACY.md](../PRIVACY.md) and is user-controlled.

Direct curl, Homebrew, and npx installation routes are inactive until immutable assets, provenance, and publication approval exist. Documentation must never turn a local packaging test into a working-release claim.
